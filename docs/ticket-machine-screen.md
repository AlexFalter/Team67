# Polybahn controls on the physical machine screen

polybahn-ticket-machine.js reuses createMachinePanel from machine-panel.js to project every purchase phase onto the actual screen mesh bounds at either station. Card swipe, authorization/decline, mobile-payment launch, CAPTCHA, printing and collection instructions occupy this display; QR scanning retains its existing live phone camera. The collection camera frames the screen and ticket tray together without a detached bottom panel.

The controls use isolated ticket-machine.css with container-relative sizing. On short screens the CAPTCHA omits redundant headings/instructions so its nine tiles, pay and cancel actions fit within the real display. Global styles, station geometry, prices and purchase/validation rules stay intact.

Validation: isolated production build and GAME_URL=<preview> node verify-ticket-machine.mjs pass both machines, actual phone QR framing, rejected/incomplete CAPTCHA, retry/cancel/reopen, saved paid ticket, tray pickup, shared inventory, round-trip fare validation and reset. Browser assertions check embedded screen positioning, desktop pay-button bounds, mobile screen bounds and mobile pay/cancel bounds. Screenshots: artifacts/ticket-captcha-0.png, ticket-screen-mobile-captcha.png, ticket-print-0.png.

The payment card now sits in a physical 3D magnetic-stripe reader below the display on both machines. Drag it left to right through the entire groove to authorize; tapping, keyboard activation and incomplete swipes do not authorize. Releasing or cancelling an incomplete drag returns the card to its start. The card view frames the display and reader together, including portrait mobile layouts. The existing deliberate bank decline, QR fallback, CAPTCHA and physical ticket collection flow remain in place. Reader geometry is isolated in `ticket-card-reader.js`.

QR scanning is automatic: keep the whole code in the phone frame and hold still while the loading bar fills (0.2 seconds settling, then 1.4 seconds scanning). Moving too quickly or losing the code resets progress. Space cannot bypass loading; Back/Escape still cancels. PubliBike already uses its automatic hold-to-scan progress mechanic. Continuous scan timing is isolated in `scan-progress.js`.
